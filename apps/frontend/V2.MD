# MicroBuilt v2 — Frontend playbook

**How to use:** open a fresh Claude Code session at the **repo root** (`micro-built/`, the pnpm monorepo on
branch `v2` of `SteffQing/micro-built`) and paste **one stage** at a time. Every stage starts by reading **§0**.
Backend plan: `apps/backend/V2.MD`; backend API changes: `apps/backend/V2_API_CHANGES.md`.

**Paths** in this file are relative to `apps/frontend/` unless they start with `packages/`, `apps/backend/` or say
"repo root". Run frontend commands inside `apps/frontend` (`cd apps/frontend && pnpm …`) or from the root as
`pnpm --filter @microbuilt/frontend <script>`.

## §0 Shared context — read before every stage

### 0.1 Facts
- Next **16.2** App Router (`src/app`, route groups `(auth)`, `(marketing)`, `(protected)`), `src/proxy.ts` (Next 16's
  middleware), React 19, TanStack Query 5, axios (`src/lib/axios.ts`), Tailwind 4 + shadcn `new-york`
  (`components.json`, tokens in `src/app/globals.css`, `@custom-variant dark`), next-themes (provider wired, **no toggle**),
  zod 3.25, recharts 2, sonner. Types are ambient `.d.ts` files in `src/types` (no imports needed).
- API: `https://api.microbuiltprime.com` (prod), `http://localhost:3003` (dev); FE prod `https://microbuiltprime.com`.
  Swagger (after BE Stage 5): `http://localhost:3003/docs`, JSON at `/docs-json`.
- **Monorepo:** this app is `@microbuilt/frontend`; the backend is `apps/backend`; `packages/shared`
  (`@microbuilt/shared`) already exports the phone rules (`normalizeNgPhone`, `isNigerianPhone`), placeholder-email
  rules (`placeholderEmail`, `isPlaceholderEmail`, `visibleEmail`) and period labels (`MONTHS`, `Month`, `periodLabel`,
  `parsePeriodLabel`, `toYm`, `parseYm`, `comparePeriods`, `nextPeriod`) — import them, never copy them. After BE
  Stage 4 it also exports `@microbuilt/shared/auth` (`type Auth`) and `@microbuilt/shared/auth-client`
  (`microBuiltClientPlugins`). On a fresh checkout run `pnpm install` at the repo root first (it builds shared).
  better-auth agent skills live at the repo root — load `better-auth-best-practices` and
  `two-factor-authentication-best-practices` in Stage 4.
- Known debt: `next lint` no longer exists in Next 16 (the `lint` script is broken), `eslint-config-next` is 15.3;
  `src/app/favicon.ico` is the create-next-app default; `<Logo>` is hard-coded black; ~100 files import
  `lucide-react`, 3 import `@tabler/icons-react`; many components hard-code colours (`#8A0806`, `#999`, `bg-white`,
  `gray-*`), so dark mode is broken; `docs/BUGS.md` lists open bugs (referenced by ID below).

### 0.2 Ground rules
- Commit at the end of every stage on `v2`; message starts `frontend:` and explains *why*; **never** add attribution
  trailers (`Co-Authored-By`, `Generated with Claude Code`). Subagents never commit.
- Frontend stages edit `apps/frontend/**` only. Never edit `apps/backend/**`; `packages/shared` only where a stage
  says so (orchestrator only, both apps must still build).
- Dependencies: `pnpm --filter @microbuilt/frontend add <pkg>@<exact version>`; versions shared with other packages
  (better-auth family, TypeScript) use `"catalog:"` from the root `pnpm-workspace.yaml`. One lockfile, at the repo root.
- The API contract is `apps/backend/V2_API_CHANGES.md` + Swagger. Never invent fields; if the backend lacks something,
  stop and note it for the backend instead of faking it.
- From Stage 1 on, every stage ends green: `pnpm exec tsc --noEmit`, `pnpm lint`, `pnpm build`.
- After Stage 2: icons only through `@/components/icon`; avatars only through `<UserAvatar>`.
  After Stage 3: no literal colours in `src/**/*.tsx` outside `src/components/ui` and brand SVG art (use tokens, §0.5).
- Look at what you changed: run `pnpm dev` (and the backend on :3003 when data is needed) and check each touched
  page in **light + dark** at **390 px and 1440 px** (Claude in Chrome or Playwright screenshots). "Builds" is not "done".
- Money is displayed with the existing `formatCurrency`; periods display as `JUNE 2026`, and are sent as `YYYY-MM`.

### 0.4 Locked decisions
| # | Decision |
|---|---|
| F1 | Auth = better-auth client, **cookie session** (httpOnly, `Domain=microbuiltprime.com`). No tokens in localStorage. Methods for customers: email + password, phone + password (SMS-verified phone), email code, magic link, passkey; optional 2FA (TOTP / code / backup codes). **Admins: password + 2FA only** — 2FA is enforced, passwordless sign-ins are refused for them and they can't add passkeys. |
| F1b | **Routing (hybrid):** JSON API and auth go through the FE origin (`/api/*`), so no CORS preflights and first-party cookies: `next.config.ts` rewrites `/api/:path((?!auth/).*)` → `${API_ORIGIN}/:path`; `src/proxy.ts` rewrites `/api/auth/*` → `${API_ORIGIN}/api/auth/*` and adds `x-mb-edge: ${EDGE_PROXY_SECRET}` + `x-mb-client-ip` (first IP of Vercel's `x-forwarded-for`) so the API's rate limits see real clients. Uploads (multipart) and file downloads go **direct** to `NEXT_PUBLIC_API_URL` (`https://api.microbuiltprime.com`) — no preflight, no Vercel proxy limits (120 s timeout, function body limits). Vercel `*.vercel.app` previews can't carry the `microbuiltprime.com` cookie — test auth on localhost or a `*.microbuiltprime.com` preview domain. |
| F2 | Icons = **Hugeicons** free set (`@hugeicons/react` + `@hugeicons/core-free-icons`, 6,000+ stroke-rounded icons, supported by shadcn's `iconLibrary`). Custom brand illustrations in `icons-illustrations.tsx` stay but use `currentColor`/tokens. |
| F3 | Avatars = **DiceBear 10** rendered locally (`@dicebear/core` + `@dicebear/styles`, style `notionists-neutral`, CC0) seeded by user id; an uploaded photo (`user.image`) wins. No calls to api.dicebear.com (rate limits, privacy). |
| F4 | Theme = next-themes, `defaultTheme="system"`, toggle (Light/Dark/System) in both headers + Settings. |
| F5 | Error reporting = **Sentry** `@sentry/nextjs` 11.x. The project already exists: `microbuilt-fe` in org `steffqing` (EU region); `NEXT_PUBLIC_SENTRY_DSN`, `SENTRY_ORG`, `SENTRY_PROJECT` and `SENTRY_AUTH_TOKEN` (org token for source maps) are in `apps/frontend/.env.local` — never print them, never create another project. |
| F6 | Payroll data (repayments, deductions, variations, dashboard metrics) is filtered by **period range** (`from`/`to` = `YYYY-MM`); real dates (sign-up date, request date) keep date pickers. |

### 0.6 Subagent protocol (wherever a stage says "parallel")
1. Split by **disjoint folders**; shared helpers (tokens, `Icon`, `UserAvatar`, filters) are built by the
   orchestrator first. The standard split: **S1** `src/components/ui/**` · **S2** other `src/components/**` +
   `src/app/**` + `src/providers/**` · **S3** `src/ui/dashboard`, `src/ui/loans`, `src/ui/loan-request`,
   `src/ui/repayments` · **S4** `src/ui/customers`, `src/ui/customer-id`, `src/ui/account-officers`,
   `src/ui/add-customer` · **S5** `src/ui/modals`, `src/ui/settings`, `src/ui/auth`, `src/ui/home`, `src/ui/tables`.
2. Brief: goal, owned folders ("edit nothing else"), §0 sections to read, acceptance commands + expected output
   (e.g. `grep -rn "lucide-react" <folders>` → empty; `pnpm exec tsc --noEmit 2>&1 | grep <folder>` → empty),
   "don't commit, don't add packages"; report = files changed, notable decisions, commands + results, leftovers.
3. Verify each return: `git diff --stat` only in its folders, rerun its checks, open 2 of its pages in the browser
   (light + dark). Failures go back to the same subagent with the output.

## Stage 4 — Auth on better-auth + hybrid routing (needs BE Stage 5)
Read §0 (F1, F1b). Backend: `/api/auth/*` (email+password, phone+password, email OTP, magic link, passkey, 2FA,
bearer, HIBP), placeholder email for phone-only users, admins limited to password + enforced 2FA.

1. **Routing (F1b).** Env: `API_ORIGIN` (server-only, dev `http://localhost:3003`), `NEXT_PUBLIC_API_URL` (same value,
   used for direct uploads/downloads), `EDGE_PROXY_SECRET` (server-only, same value as the API).
   `next.config.ts` → `rewrites()`: `{ source: '/api/:path((?!auth/).*)', destination: `${API_ORIGIN}/:path` }`.
   `src/proxy.ts`: for `/api/auth/:path*` return `NextResponse.rewrite(new URL(pathname + search, API_ORIGIN),
   { request: { headers } })` with `x-mb-edge` and `x-mb-client-ip` (first entry of the incoming `x-forwarded-for`)
   added; keep `x-current-path` for pages; matcher covers `/api/auth/:path*` + pages, not `_next`, icons, `/monitoring`.
2. Clients: `src/lib/axios.ts` → `api` with `baseURL: '/api'` (JSON, same origin) and `uploads` with
   `baseURL: NEXT_PUBLIC_API_URL`, `withCredentials: true` (multipart only — no custom headers, so no preflight).
   Drop the bearer interceptor and all token storage (`src/store/auth.ts`). On 401 → `/login?next=<path>` (except
   auth/public routes); on 403 `TWO_FACTOR_SETUP_REQUIRED` → `/settings/security?setup=2fa`.
   Move every upload call (payroll sheet, validate, avatar, bulk customers, liquidation proof) and file download to `uploads`.
3. Add `"better-auth": "catalog:"` and `"@better-auth/passkey": "catalog:"` to `package.json`,
   `pnpm --filter @microbuilt/frontend add qrcode.react@4.2.0`, `pnpm install` at the root. `src/lib/auth-client.ts`:
   `createAuthClient({ basePath: '/api/auth', plugins: microBuiltClientPlugins({ onTwoFactorRedirect: () =>
   router.push('/two-factor') }) })` — `createAuthClient` from `better-auth/react`, the plugins from
   `@microbuilt/shared/auth-client` (built from the server's plugin list, so the client can't drift from what the
   API exposes; same-origin, so no `baseURL`). Use `import type { Auth } from '@microbuilt/shared/auth'` wherever server
   types are needed (e.g. `typeof authClient.$Infer.Session`). Phone and placeholder rules come from
   `@microbuilt/shared` (`normalizeNgPhone`, `placeholderEmail`, `isPlaceholderEmail`, `visibleEmail`) — no local
   copies; placeholders are never displayed.
4. Screens (replace `src/lib/mutations/user/auth.ts` entirely):
   | Screen | Call |
   |---|---|
   | Sign-up (email, optional phone) | `signUp.email({ name, email, password, phoneNumber? })` → email code step |
   | Sign-up (phone only) | `signUp.email({ name, email: placeholderEmail(p), password, phoneNumber })` → `phoneNumber.sendOtp` → `phoneNumber.verify` → `signIn.phoneNumber` |
   | Email code step (`/verify-code`) | `emailOtp.verifyEmail({ email, otp })`; resend `emailOtp.sendVerificationOtp({ email, type: 'email-verification' })` |
   | Login `/login` | tabs **Email** (`signIn.email`), **Phone** (`signIn.phoneNumber`; unverified phone → SMS verify then retry), **Email code** (`emailOtp.sendVerificationOtp({ type: 'sign-in' })` → `signIn.emailOtp`), **Magic link** (`signIn.magicLink({ email, callbackURL: origin + '/dashboard' })` → "check your inbox"); **Sign in with passkey** button + conditional UI (`autocomplete="username webauthn"`, `signIn.passkey({ autoFill: true })`). Errors: `EMAIL_NOT_VERIFIED` → code step; `FORBIDDEN` → inactive / admins-can't-use-this message; pwned password → clear message |
   | 2FA challenge `/two-factor` | `twoFactor.verifyTotp` / `sendOtp` + `verifyOtp` / `verifyBackupCode`; "trust this device" checkbox for customers only (admins confirm every sign-in) |
   | Forgot (email) | `requestPasswordReset({ email, redirectTo: origin + '/reset-password' })` |
   | Forgot (phone) | `phoneNumber.requestPasswordReset` → SMS code + new password → `phoneNumber.resetPassword` |
   | Reset | `resetPassword({ newPassword, token })`; no token → `/forgot-password` (BUG-014); fix "securd" (BUG-013) |
   | Settings → **Security** (`/settings/security`) | change password (`changePassword({ …, revokeOtherSessions: true })`); 2FA enable (`twoFactor.enable({ password })` → QR from `totpURI` via `qrcode.react` → `verifyTotp`) / disable / regenerate backup codes (show once, copy/download); passkeys list/add/rename/delete (customers only — hidden for admins); add or change email — replaces a placeholder (`emailOtp.requestEmailChange({ newEmail })` → code to the new address → `emailOtp.changeEmail({ newEmail, otp })`); change phone (`phoneNumber.sendOtp` → `phoneNumber.verify({ phoneNumber, code, updatePhoneNumber: true })`); active sessions (`listSessions`) + `revokeOtherSessions` |
   | Logout | `signOut()` → `queryClient.clear()` → `Sentry.setUser(null)` → `router.replace('/login')` |

   If a plugin field (e.g. `phoneNumber` on sign-up) is rejected at the type level, add `inferAdditionalFields(...)`
   from `better-auth/client/plugins` — don't cast to `any`.
5. Gating: `src/proxy.ts` also does optimistic redirects with `getSessionCookie(request)` (`better-auth/cookies`):
   no cookie + protected route → `/login?next=`; cookie + auth route → `/dashboard` — a UX hint only. `useUserProvider`:
   `authClient.useSession()` + `GET /user` (role, `twoFactorEnabled`; `Sentry.setUser({ id })`); admins without 2FA
   are sent to Security setup and can't leave it until 2FA is on. Remove localStorage checks and redirect loops;
   full-page skeleton while loading.
6. Queues link: `handleViewQueues` opens `${NEXT_PUBLIC_API_URL}/queues` (cookie auth; super admin only).
7. Verify in the browser against the local backend: every row of the table above; passkey register → sign out →
   passkey sign-in (Chrome's virtual authenticator in DevTools works on localhost); TOTP enable → sign-in asks for a
   code → trusted device skips it next time (customer); admin magic link / email code / passkey refused with the
   "Admins sign in with password and 2FA" message; admin without 2FA forced to setup; refresh
   keeps the session; a direct upload sends the cookie. **Measure**: DevTools timing for 5 GETs and 5 PATCHes via
   `/api` vs direct to the API — record the numbers in the commit message.

**Done when:** all flows pass, no `localStorage` auth reads remain, no CORS preflight on JSON calls (Network tab),
tsc/lint/build green. Commit.
